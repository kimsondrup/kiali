=== querypb

Grafana Tempo's query IDL, cut down to what Kiali reads and generated with
`protoc-gen-go`.

It carries the streaming search RPC Kiali calls, its request, and the search answer
both the gRPC and the HTTP transport return. Tempo's write path, its block and tag
RPCs, and the trace detail are left out. Span attributes come from the published
`go.opentelemetry.io/proto/otlp` module rather than the fork of the OTLP model Tempo
carries under its own proto package, so no OTLP type is generated here.

The proto package stays `tempopb`, because it names the gRPC method Kiali invokes:
`/tempopb.StreamingQuerier/Search`.

==== How it is produced

`tempo.proto` is not written here. `hack/tempo-querypb.allow` names the service, the
RPC, the messages and the fields Kiali reads, and `hack/gen-tempo-protos.sh` cuts
upstream's `pkg/tempopb/tempo.proto` down to those, taking every field number and type
from upstream. Moving to a newer Tempo is a new entry in that script's
`TEMPO_VERSIONS` and a re-run; the diff is then new `reserved` lines naming what
upstream added, and any other hunk is a real change on a surface Kiali touches.

The allow-list carries names and never numbers. A name is what a rename breaks, so a
field Kiali reads that upstream renames stops the generator rather than quietly
becoming a zero, and a number this repository could get wrong is a number this
repository does not write.

A number the cut drops is `reserved` and named after the field upstream declares
there. That is documentation, not a safety device - the numbers come from upstream
either way - but it makes an upgrade's diff read as a list of upstream's additions,
and `protoc` then rejects anyone declaring something else at one of those numbers.

==== What the generator asserts

* `pkg/tempopb` is still carved out as Apache-2.0 in Tempo's `LICENSING.md`.
* Every allow-listed name exists, with the same number and the same type, in *every*
  release in `TEMPO_VERSIONS` and not just the one the IDL is cut from. The range Kiali
  supports is therefore checked rather than claimed.
* Tempo's fork of the OTLP common model numbers `KeyValue` and `AnyValue` as the pinned
  `opentelemetry-proto` release does. Rewriting one to the other is only sound while
  that holds, and a drift would be read as the wrong field with no error anywhere.
* Every type a kept field or the RPC names is a proto3 scalar, a message the cut keeps,
  or the rewritten OTLP model. Upstream retyping a field Kiali reads to something
  Tempo-local stops the generator instead of dragging another upstream model in.

==== The Tempo versions this is for

`TEMPO_VERSIONS` names v2.2.0 to v3.1.0, eleven releases over three years, and every
allow-listed name is asserted to carry the same number and type in all of them. There is
no declared ceiling.

The floor is not the IDL's. A v2.0.0 answer decodes into these stubs: every name the
allow-list carries that v2.0.0 declares, it declares at the same number, and the three it
does not have yet - `SpansPerSpanSet`, `spanSets` and `SpanSet.attributes` - are simply
absent from the answer. Two other things decide the floor, and both land on v2.2.0:

* `StreamingQuerier` first appears at v2.2.0. An older Tempo answers
  `Unimplemented: unknown service tempopb.StreamingQuerier`.
* Both transports emit `| select(...)`, which TraceQL gained at v2.2.0. Tempo 2.0.0
  answers HTTP 400 naming the column it cannot parse.

So no decoder tolerance widens the floor, and v2.1.0 is unverified rather than excluded.
What holds the ceiling open is not the IDL's contents either: it is `DiscardUnknown` on
the HTTP decode and proto3's own dropping of an undeclared field over gRPC. Closing it
takes a renumbering or a removal on a name the allow-list carries, which is what the
generator refuses to generate through.

==== What is left out, and why that is the point

The allow-list is the whole of Kiali's Tempo surface. A field read by nothing is not
declared, however harmless it looks, because declaring it is the only way this
repository can be wrong about it.

`SearchMetrics` is the case that settles the rule. Kiali reads no field of it, and it
is the one message in Tempo's history whose numbers were reused with a new meaning:
3, 4 and 5 were `inspectedBlocks`, `skippedBlocks` and `skippedTraces` before v2.2.0
and are `totalBlocks`, `completedJobs` and `totalJobs` after it, at the same wire type.
A client holding the old names decodes the new answer silently and wrongly. Kiali was
never exposed to it - v2.2.0 both reused those numbers and introduced
`StreamingQuerier`, so no Tempo exists that Kiali's gRPC client can reach and that
still means the old things - but keeping the message needed an exception to the rule
and dropping it needed nothing.

Also out: `SearchResponse.metrics`, as the consequence; `SearchRequest.Tags`, a map
never set because both transports fold query tags into the TraceQL expression instead;
and `TraceSearchMetadata.startTimeUnixNano` and `durationMs`, read by nothing.
Only `Span.startTimeUnixNano` is read.

Dropping a field changes nothing on either transport. Binary proto3 drops an
undeclared field itself, and the HTTP decode passes `DiscardUnknown`, so what arrives
at a number the IDL reserves is dropped exactly as it was before. The envelope check in
`unmarshal` reads the raw JSON key map rather than the decoded message, so it still
accepts a `metrics` key.

==== Reading the result

Two things the IDL cannot say, which the code that reads it relies on:

* `traceID` is hex and Tempo does not zero-pad it, so about one trace in sixteen
  arrives shorter than 32 characters. Callers pad.
* `SpansPerSpanSet` bounds the spans returned per matching trace, and Tempo defaults it
  to 3, which loses spans Kiali draws.

==== Regenerating

`hack/gen-tempo-protos.sh` rewrites `tempo.proto` and regenerates `tempo.pb.go` and
`tempo_grpc.pb.go`. It fetches protoc, the plugins and the OpenTelemetry protos at
pinned versions, so the output is reproducible; set `PROTOC` to use a protoc already
installed. It needs a network, because what it emits is upstream's.
